# 数据目录启动锁

同一数据目录只允许一个服务实例。服务在清理下载暂存文件、打开身份数据库前，先取得 `server-lock.sqlite` 的 SQLite 排他事务锁，并持有连接直到退出。进程异常退出时操作系统自动释放文件锁；残留文件及 PID 复用不会阻止下次正常启动。同一进程的多个连接也必须竞争这把锁。

`server.lock` 在新版本中是保留的目录标记，不是需要定期删除的垃圾文件。目录创建是原子的，启动中断不会留下写了一半的 JSON/PID 标记。旧版本只认识数字 PID 文件，遇到目录会停止启动，因此不会绕过新服务的锁。

升级时兼容旧的数字 PID 文件：PID 已不存在时可迁移；PID 仍存在时，只有能够确认该进程的启动时间晚于锁文件修改时间（另留两秒时间精度余量），才确认 PID 已被复用并迁移。Windows 通过只读 `Get-Process` 查询启动时间，其他系统通过 `ps` 查询。查询失败、进程信息无权访问、时间不足以证明 PID 复用，或旧锁内容无效时保守停止，不清理传输数据。应先从旧服务托盘退出，再启动新版；无法确认的旧锁需要在确认原服务已退出后人工检查。

正常退出会释放 SQLite 连接，保留锁数据库和目录标记供下次使用。服务运行时不要手工删除、替换或复制这些锁文件。并发启动新旧两个版本进行升级不受支持，应先退出旧版再升级。
